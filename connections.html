Connections

Which venues LONA can reach, what those connections are permitted to do, and when each was last checked. Everything on this page is a mirror. Nothing on it is a control that can start anything.

🔒 This page holds no credentials, and cannot

There is no field on this page to enter an API key, no storage that could hold one, and no request from this page that carries one. That is not an omission to be filled in later — it is the design.

The page never signs. It writes intent; the executor reads intent. Keys live in the operating system's credential store on the machine that runs the executor, are read once at startup, and are never transmitted, never logged and never rendered. The executor holds no inbound port: it polls outward and nothing can reach in.

The consequence worth stating plainly: a total compromise of this website cannot move a single coin. Not because the login is strong, but because there is nothing here to steal. On 27 August the Access policy in front of this site was misconfigured twice in one morning. That cost a broken data feed on a phone. It could not have cost money, and this is the reason.

How a decision reaches a venue

Writing the executor

Set an explicit User-Agent, and never inherit a library default. Something like lona-executor/1.

Measured on 29 August 2026, five ways against this API within seconds of each other: curl’s default returned 200, python-requests 200, a browser string 200, an empty agent 200 — and Python-urllib/3.11 returned 403. Bot protection on this hostname keys off that exact string. Not rate limiting, not caching, not the query string; each was ruled out by test rather than by reasoning.

Nothing running today is affected — the watchdog and the daily consistency check read GitHub, which serves that agent a clean 200. But an executor written in Python with urllib, which is what every other check in this project uses, would be refused on every poll. The symptom reads like a network fault, a token fault or a broken worker long before anyone suspects the name the library chose to introduce itself by.

Found by accident: one 403 in a burst of requests, first dismissed as rate limiting. That was a guess, and it was only caught because the guess was checked. A default you did not choose is a decision someone else made for you.

Stopping it

A halt control belongs here and is not built yet. When it is, it will be able to do exactly one thing: set halt. It will have no control that enables trading, raises a cap, or adds a venue — those require the executor's own configuration, deliberately.

not wired

Why it is disabled rather than absent: writing intent needs a verified identity, and identity comes from the Access header. api.lonaquant.com sits deliberately outside Access so the executor — which has no browser and cannot log in — can poll it. So a POST from this page arrives with no identity and is refused, correctly. The fix is a second hostname on the same worker, behind Access, carrying only the write path. Until that exists, a button here would be a button that always fails, and a safety control that does nothing is worse than none.

Adding a venue

A venue is not connected by filling in a form. In order, and the page is last:

  • A venue adapter — universe, candles, funding, and a place-order path. The second implementation is what forces the interface to be one.
  • An archive and its funding history, so the venue can be measured before it is traded.
  • Finding 008 re-measured on it, pre-registered, before any money. The universe rule is “top 20 by dollar volume on that venue”, so a new venue is a new universe and a new strategy until proven otherwise.
  • Venue-scoped intent, so one leg can be halted without halting all.
  • This page, which only ever shows the four above.

OKX is the one venue where steps two and three are already done. 301 markets, 5.7 years, 100% funding coverage: +26.4% CAGR, Sharpe 1.09, worst drawdown −30%, t 2.1 — pre-registered before the data was downloaded, and it confirmed. That is why it is on this page and Binance is not.

And the open question, which is research and not engineering: two venues is not two copies of LONA. Two independent books, each top-20 on its own venue, is a different strategy from one merged universe ranked across both — different concentration, different correlation, different drawdown. Finding 008 describes neither. Nothing here should be traded on two venues until that has a number attached.
